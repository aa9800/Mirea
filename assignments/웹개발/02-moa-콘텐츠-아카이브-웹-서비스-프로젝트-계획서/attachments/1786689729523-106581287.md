# 프로젝트 계획서

## 1. 프로젝트명
Moa - 나의 취향을 모으는 콘텐츠 아카이브

## 2. 프로젝트 개요
Moa는 영화, 드라마, 책, 음악의 정보를 사용자가 일일이 손으로 입력하는 기록장이 아니라, 외부 콘텐츠 검색 기능으로 원하는 작품을 찾아 선택하면 제목·이미지·장르·연도·제작자 같은 기본 정보가 자동으로 채워지고, 사용자는 별점·감상 상태·한줄평·즐겨찾기·개인 태그 같은 자신만의 취향 정보만 덧붙여 기록하는 개인 콘텐츠 아카이브 웹페이지입니다. 검색으로 찾을 수 없는 콘텐츠는 "직접 추가" 기능으로 보완합니다.

## 3. 개발 배경 및 목적
- 기존의 직접 입력 방식은 제목, 장르, 연도 등 반복적인 정보를 매번 손으로 채워야 해서 꾸준히 쓰기엔 번거로웠습니다. 이를 개선해 **검색 → 선택 → 개인 기록**만 남기는 짧고 자연스러운 흐름으로 바꾸는 것이 이번 개편의 핵심 목적입니다.
- 외부 API 연동, 검색·필터·정렬, 즐겨찾기·태그 같은 사용자 인터랙션을 실제 서비스에 가까운 수준으로 단계적으로 구현하며 바이브 코딩 개발 흐름을 학습합니다.
- 로그인, 서버, 데이터베이스 없이도 실제로 쓸 수 있는 결과물을 localStorage 기반으로 완성하는 경험을 쌓습니다.

## 4. 주요 사용자
- 영화, 드라마, 책, 음악 등 다양한 콘텐츠를 즐기고, 감상 기록을 편하게 남기고 다시 찾아보고 싶은 개인 사용자 (개발자 본인)
- 여러 사람이 함께 쓰는 서비스가 아니라, 한 사람이 자신의 취향을 기록하는 개인용 아카이브입니다.

## 5. 핵심 서비스 흐름
```
콘텐츠 종류 선택
→ 콘텐츠 검색
→ 외부 API 검색 결과 확인
→ 원하는 콘텐츠 선택
→ 제목·이미지·장르·연도·제작자 등 기본 정보 자동 입력
→ 사용자가 별점·감상 상태·한줄평 등 작성
→ 내 Moa에 저장
```

외부 API에서 가져오는 정보와 사용자가 직접 기록하는 정보를 명확히 구분합니다.

| 구분 | 항목 |
| --- | --- |
| 외부 API 제공 정보 | 제목, 원제, 포스터/표지/앨범 이미지, 콘텐츠 종류, 장르, 개봉·출판·발매년도, 감독/저자/아티스트, 기본 작품 정보, 외부 콘텐츠 ID |
| 사용자 직접 기록 정보 | 별점, 감상 상태, 한줄평, 즐겨찾기, 개인 태그, 등록 날짜 |

외부 검색이 기본 등록 방식이며, 검색으로 찾지 못한 콘텐츠는 "직접 추가"로 보완하는 보조 방식입니다.

## 6. 프로젝트 범위 (필수 기능 / 향후 확장)

**필수 기능 (이번 프로젝트에서 구현)**
- 콘텐츠 종류 선택 및 외부 콘텐츠 검색
- 검색 결과 확인 및 선택 → 내 Moa 저장
- 직접 추가 (검색되지 않는 콘텐츠 보조 등록)
- 별점 / 한줄평 / 감상 상태 / 즐겨찾기 / 개인 태그
- 수정 / 삭제
- 중복 등록 방지
- 내 아카이브 검색 (외부 검색과 구분)
- 필터 / 정렬
- 아카이브 요약
- localStorage 저장
- 반응형 UI

**향후 서비스 확장 (이번 프로젝트 범위 밖)**
- 회원가입 / 로그인
- 서버 / 데이터베이스
- 여러 기기 간 데이터 동기화, 사용자별 아카이브
- 친구와 취향 공유, 콘텐츠 추천, 평점 통계
- 데이터 백업 / 내보내기, 클라우드 저장

## 7. 주요 기능
1. 콘텐츠 종류 선택 (영화 / 드라마 / 책 / 음악)
2. 외부 콘텐츠 검색 (제목 기반)
3. 검색 결과 확인 및 콘텐츠 선택
4. 선택한 콘텐츠의 기본 정보 자동 입력
5. 별점 · 감상 상태 · 한줄평 · 즐겨찾기 · 개인 태그 기록
6. 내 Moa에 저장
7. 직접 추가 (검색 결과에 없는 콘텐츠 등록)
8. 중복 등록 방지
9. 내 아카이브 카드 목록 표시
10. 카드 상세 보기
11. 수정
12. 삭제 (Undo 고려)
13. 내 아카이브 검색
14. 필터 (콘텐츠 종류 + 즐겨찾기 + 감상 상태)
15. 정렬 (등록순 · 별점순 · 가나다순)
16. 카드에서 즐겨찾기 / 감상 상태 빠른 변경
17. 아카이브 요약 (전체 및 종류별 개수)
18. 빈 화면 / 검색 결과 없음 안내
19. 로딩 / 오류 상태 안내
20. 반응형 레이아웃

## 8. 각 기능에 대한 상세 설명

### 8-1. 콘텐츠 종류 선택
영화 / 드라마 / 책 / 음악 버튼을 화면 상단에 배치합니다. 선택한 종류에 따라 검색에 사용할 외부 API와 검색 결과 형식이 달라지며, 현재 선택된 종류는 색상이나 밑줄 등으로 명확하게 강조 표시합니다.

### 8-2. 외부 콘텐츠 검색
검색창에 제목을 입력하면 선택된 콘텐츠 종류에 맞는 외부 API로 검색을 요청합니다. 검색 편의를 위해 다음을 함께 구현합니다.
- 검색 버튼 클릭 또는 Enter 키로 검색 실행
- 일정 글자 수 이상 입력했을 때만 검색 가능
- 입력할 때마다 API를 과도하게 호출하지 않도록 debounce(입력이 잠시 멈췄을 때 요청) 방식 적용
- 검색 중 로딩 상태, 결과 없음, API 오류 상태를 각각 안내
- 새 검색 시 이전 검색 결과를 지우고 새 결과로 교체
- 검색어 초기화 버튼 제공

### 8-3. 검색 결과 확인 및 선택
검색 결과는 이미지, 제목, 연도, 콘텐츠 종류, 감독/저자/아티스트 등 대표 정보를 담은 리스트(또는 카드)로 여러 개 표시됩니다. 사용자가 원하는 항목을 클릭하면 다음 단계(기록 작성)로 넘어갑니다.

### 8-4. 기본 정보 자동 입력 및 개인 기록 작성
콘텐츠를 선택하면 제목, 이미지, 장르, 연도, 제작자 등 외부 API 정보가 자동으로 채워진 화면(또는 모달)이 열리고, 사용자는 별점 · 감상 상태 · 한줄평 · 즐겨찾기 · 개인 태그를 추가로 입력합니다. 모든 항목을 다 채워야 저장되는 방식이 아니라 필수/선택 항목을 구분합니다.
- 필수: 콘텐츠 선택
- 선택: 별점, 한줄평, 감상 상태, 즐겨찾기, 개인 태그

이렇게 하면 사용자가 콘텐츠를 우선 빠르게 저장하고, 나중에 상세 정보를 채우거나 수정할 수 있습니다.

### 8-5. 직접 추가
외부 API 검색에 나오지 않는 콘텐츠는 "직접 추가" 버튼을 통해 제목, 콘텐츠 종류, 장르, 이미지 URL(또는 이미지 없이 등록), 연도, 제작자/저자/아티스트, 별점, 한줄평을 사용자가 직접 입력해 등록할 수 있습니다. 외부 검색이 기본이고 직접 추가는 보조 기능입니다.

### 8-6. 중복 등록 방지
같은 콘텐츠를 실수로 다시 등록하지 않도록, 외부 API의 콘텐츠 ID(externalId) 또는 제목+종류 조합으로 이미 저장된 콘텐츠인지 확인합니다. 이미 등록되어 있다면 "이미 내 Moa에 등록된 콘텐츠입니다." 안내를 표시하고, 가능하면 기존 기록으로 바로 이동할 수 있게 합니다.

### 8-7. 내 아카이브 카드 목록 및 상세 보기
저장한 콘텐츠는 포스터/표지/앨범 이미지를 중심으로 한 카드 형태로 표시하며, 카드에는 이미지, 제목, 콘텐츠 종류, 장르, 연도, 별점, 감상 상태, 즐겨찾기 여부, 한줄평 일부를 보여줍니다. 카드를 클릭하면 큰 이미지, 전체 정보, 개인 태그, 등록 날짜를 보여주는 상세 화면(또는 모달)이 열리고, 여기서 수정 · 삭제 · 즐겨찾기 기능을 제공합니다.

### 8-8. 감상 상태
콘텐츠마다 진행 상태를 기록합니다(예: 보고 싶음 / 감상 중 / 완료). 책은 읽고 싶음 / 읽는 중 / 완료처럼 자연스럽게 표현하고, 음악처럼 상태 구분이 어색한 경우 공통 상태 체계를 그대로 사용하거나 상태 입력을 생략할 수 있게 해서 구현 복잡도를 과도하게 높이지 않습니다.

### 8-9. 즐겨찾기
특히 좋아하는 콘텐츠는 하트 또는 북마크 아이콘으로 즐겨찾기를 설정/해제할 수 있으며, 카드에서 바로 조작할 수 있습니다. 즐겨찾기한 콘텐츠만 모아보는 필터도 제공합니다.

### 8-10. 개인 태그
API가 제공하는 공식 장르와 별개로, 사용자가 자신만의 기준(예: 인생영화, 다시볼것, 힐링, 공부용, 여행할때듣는음악, 추천받음)으로 콘텐츠를 분류할 수 있는 선택 입력 항목입니다.

### 8-11. 내 아카이브 검색
외부 콘텐츠를 검색하는 검색(새 콘텐츠를 찾기 위한 검색)과, 이미 저장한 콘텐츠를 찾는 "내 아카이브 검색"을 화면과 기능 모두 명확히 구분합니다. 내 아카이브 검색에서는 제목, 장르, 제작자/저자/아티스트, 개인 태그를 검색 대상으로 합니다.

### 8-12. 필터 및 정렬
필터는 콘텐츠 종류(전체/영화/드라마/책/음악)와 추가 조건(즐겨찾기, 보고 싶음, 감상 중, 완료)을 동시에 적용할 수 있게 합니다. 정렬은 최근 등록순, 오래된 등록순, 별점 높은순, 별점 낮은순, 제목 가나다순 중에서 선택하며, 필터·검색 결과에도 동일하게 적용됩니다.

### 8-13. 빠른 조작과 수정 · 삭제
즐겨찾기 설정, 감상 상태 변경처럼 자주 쓰는 조작은 상세 화면까지 들어가지 않고 카드에서 바로 처리할 수 있게 합니다. 반면 수정과 삭제처럼 신중해야 하는 조작은 상세 화면이나 명확한 버튼을 통해서만 실행되도록 합니다. 수정 가능한 항목은 별점, 한줄평, 감상 상태, 즐겨찾기, 개인 태그이며, 외부 API로 받아온 제목·이미지 등 작품 기본 정보는 원칙적으로 유지하되 직접 추가한 콘텐츠는 해당 정보도 수정할 수 있습니다. 삭제 시에는 확인 절차를 거치며, 가능하다면 삭제 직후 "삭제되었습니다. 되돌리기" 형태의 짧은 Undo도 고려합니다.

### 8-14. 아카이브 요약
화면 상단에 전체 콘텐츠 수와 영화/드라마/책/음악별 개수(예: 전체 42, 영화 14, 드라마 8, 책 10, 음악 10)를 표시하고, 여유가 있으면 즐겨찾기 수·완료한 콘텐츠 수도 함께 보여줍니다. 등록, 수정, 삭제 시 개수가 자동으로 갱신됩니다.

### 8-15. 빈 화면 및 오류·로딩 처리
아카이브가 비어 있을 때는 "아직 Moa에 저장한 콘텐츠가 없어요. 좋아하는 영화, 책, 음악을 검색해 추가해보세요." 같은 안내와 콘텐츠 추가 버튼을 보여주고, 이는 "검색 결과가 없음" 상태와는 다르게 구분해서 처리합니다. 외부 API 사용 중 발생할 수 있는 검색 중 / 검색 결과 없음 / API 요청 실패 / 네트워크 오류 / 이미지 로딩 실패 상태 각각에 대해 명확한 안내 문구를 표시해서, 사용자가 지금이 로딩 중인지 오류인지 구분할 수 있게 합니다.

### 8-16. 이미지 처리
API에서 이미지가 제공되면 카드와 상세 화면에 그대로 표시하고, 이미지가 없거나 로딩에 실패한 콘텐츠에는 깨진 이미지 대신 콘텐츠 종류별 기본 placeholder 이미지를 표시합니다.

## 9. 화면 구성
- **헤더 영역**: 서비스 이름(Moa)과 짧은 소개 문구
- **콘텐츠 종류 선택 영역**: 영화/드라마/책/음악 탭, 선택된 종류 강조 표시
- **외부 검색 영역**: 검색창 + 검색 버튼 + 초기화 버튼, 검색 결과 리스트(이미지·제목·연도·종류·대표 정보), 로딩/오류/결과 없음 상태 표시
- **기록 작성 화면(모달)**: 선택한 콘텐츠의 자동 입력 정보 + 별점·감상 상태·한줄평·즐겨찾기·개인 태그 입력 폼 + 저장 버튼, "직접 추가" 진입 버튼 포함
- **아카이브 요약 영역**: 전체 및 종류별 콘텐츠 개수 표시, 등록·수정·삭제 시 자동 갱신
- **내 아카이브 검색 · 필터 · 정렬 영역**: 외부 검색과 구분되는 별도 검색창, 필터 버튼, 정렬 선택창
- **내 아카이브 카드 목록 영역**: 이미지 중심 카드 그리드, 카드 클릭 시 상세 모달 오픈, 빈 상태/검색 결과 없음 안내 포함
- **카드 상세 모달**: 큰 이미지, 전체 정보, 수정 · 삭제 · 즐겨찾기 버튼
- PC에서는 여러 열 카드 그리드, 태블릿은 화면 크기에 맞게 열 수 조절, 모바일은 한 열 또는 두 열로 표시하는 반응형 레이아웃으로 구성하며, 검색창·필터·정렬 컨트롤이 작은 화면에서 겹치거나 잘리지 않도록 합니다.

## 10. UI/UX 디자인 방향
Moa는 단순 CRUD 관리 페이지가 아니라, 콘텐츠 이미지가 중심이 되는 현대적인 콘텐츠 플랫폼처럼 보이는 것을 지향합니다.
- 콘텐츠 이미지 중심의 카드, 통일된 이미지 비율, 둥근 카드 모서리
- 충분한 여백을 두어 정보가 많아도 복잡해 보이지 않게 구성
- 콘텐츠 종류별 배지, 별 아이콘(★, ☆)을 이용한 별점 시각화
- 버튼과 입력창의 명확한 상태 표시(hover, 선택됨 등)와 자연스러운 hover 효과
- 현재 선택된 필터·콘텐츠 종류는 색상이나 강조 표시로 뚜렷하게 구분
- 외부 검색 영역과 내 아카이브 영역을 시각적으로 구분해 사용자가 "새로 찾는 중"인지 "이미 저장한 것을 보는 중"인지 헷갈리지 않게 함
- 로딩·오류·빈 화면 상태에도 각각 명확한 안내 문구와 최소한의 시각 요소(아이콘 등) 사용
- 모바일 화면 대응을 기본으로 고려
- 지나치게 많은 색상이나 화려한 애니메이션은 사용하지 않고 전체적으로 깔끔하고 미니멀하게 구성

## 11. 사용 기술
- **HTML5**: 시맨틱 태그를 활용한 페이지 구조 작성
- **CSS3**: Flexbox와 Grid를 이용한 레이아웃, 미디어 쿼리를 이용한 반응형 스타일링
- **JavaScript (Vanilla JS)**: 검색, 선택, 등록, 수정, 삭제, 필터, 정렬, 아카이브 요약 등 전체 동작 로직
- **fetch API**: 외부 콘텐츠 검색 API 호출
- **localStorage**: 사용자가 Moa에 저장한 콘텐츠 데이터(개인 기록 포함)를 브라우저에 저장
- 로그인, 서버, 데이터베이스는 이번 프로젝트의 필수 구현 기능으로 지정하지 않으며, 향후 확장 단계에서 고려할 수 있는 항목입니다. (자세한 내용은 17번 향후 확장 계획 참고)

## 12. 외부 API 구성 방향
영화/드라마, 책, 음악은 필요한 정보(장르, 제작자 정보 등)의 형태가 서로 다르기 때문에, 하나의 API로 모든 종류를 무리하게 처리하지 않고 콘텐츠 종류별로 적절한 외부 API를 각각 연결하는 것을 원칙으로 합니다.

이 단계(PROJECT_PLAN.md)에서는 특정 API를 무조건 확정하기보다, API를 선정할 때 아래 조건을 먼저 확인하도록 계획합니다.
- 무료 또는 학습용으로 사용 가능한지
- 검색 기능을 제공하는지
- 이미지 URL을 제공하는지
- 한국어 검색이 가능한지
- 브라우저(클라이언트)에서 직접 호출할 수 있는지 (CORS 등 제약 확인)
- 인증 방식이 지나치게 복잡하지 않은지
- 요청 제한(rate limit)이 학습 프로젝트 사용에 적절한지

API 키를 프론트엔드 코드에 그대로 노출해야 하는 API는 보안상 문제가 될 수 있다는 점을 계획서에 명시해두며, 필요하다면 향후 서버 또는 간단한 프록시 구조를 통해 API 키를 보호하는 방식으로 발전시킬 수 있습니다.

**콘텐츠 종류별 후보 API (예시)**

서버 없이 브라우저에서 바로 호출 가능한지를 최우선 기준으로, 아래 API들을 우선 후보로 검토합니다. 실제 채택 여부는 15번 개발 단계 중 4~6단계(외부 API 연동)에서 최종 확정합니다.

| 콘텐츠 종류 | 후보 API | 선택 이유 |
| --- | --- | --- |
| 영화 / 드라마 | TMDB (The Movie Database) API | 무료, 검색·이미지·장르 제공, 브라우저에서 직접 호출 가능 |
| 음악 | iTunes Search API | 인증 키 없이 사용 가능, CORS 제약 없음, 앨범 이미지·아티스트 정보 포함 |
| 책 | Google Books API | 별도 인증 없이도 검색 가능, CORS 지원. 다만 국내 도서 검색 정확도는 알라딘 · 네이버 책 API보다 낮을 수 있어 참고용으로 우선 검토 |

알라딘, 네이버 책 API처럼 국내 도서 데이터가 더 풍부한 API는 브라우저 직접 호출이 막혀 있어 서버(프록시)가 필요한 경우가 많으므로, 이번 프로젝트(서버 없음) 범위에서는 1순위 후보로 두지 않습니다. 향후 서버를 도입하는 확장 단계에서 교체를 고려할 수 있습니다.

## 13. 데이터 구조
사용자가 Moa에 저장하는 콘텐츠는 다음과 같은 정보를 가지도록 합니다.

```
{
  id: "콘텐츠를 구분하는 고유 식별자",
  externalId: "외부 API가 제공하는 콘텐츠 고유 ID (중복 등록 확인에 사용, 직접 추가 시 없음)",
  title: "제목",
  originalTitle: "원제",
  type: "영화 | 드라마 | 책 | 음악",
  genre: "장르",
  imageUrl: "포스터 / 표지 / 앨범 이미지 URL",
  releaseDate: "개봉 · 출판 · 발매년도",
  creator: "감독 / 저자 / 아티스트",
  rating: "1~5 사이의 내 별점",
  review: "한줄평",
  status: "보고 싶음 | 감상 중 | 완료 (또는 콘텐츠 종류에 맞는 표현)",
  favorite: "즐겨찾기 여부 (true / false)",
  tags: "개인 태그 목록",
  createdAt: "등록 일시",
  updatedAt: "마지막 수정 일시",
  source: "api | manual (외부 검색으로 등록했는지, 직접 등록했는지 구분)"
}
```

localStorage에는 외부 콘텐츠 데이터 전체가 아니라, 사용자가 선택한 콘텐츠의 필요한 기본 정보와 사용자의 개인 기록만 함께 저장합니다.

## 15. 개발 단계 및 순서
1. **1단계**: 기본 화면과 카드 UI 구성
2. **2단계**: localStorage 기반 직접 등록 / 조회 / 수정 / 삭제 구현
3. **3단계**: 내 아카이브 검색 / 필터 / 정렬 구현
4. **4단계**: 영화·드라마 외부 검색 API 연동
5. **5단계**: 책 외부 검색 API 연동
6. **6단계**: 음악 외부 검색 API 연동
7. **7단계**: 검색 결과 → Moa 저장 과정 연결
8. **8단계**: 이미지 및 상세 정보 표시
9. **9단계**: 즐겨찾기 / 감상 상태 / 개인 태그 구현
10. **10단계**: 중복 등록 방지 구현
11. **11단계**: 아카이브 요약 구현
12. **12단계**: 로딩 / 오류 / 빈 화면 처리
13. **13단계**: 반응형 디자인 적용
14. **14단계**: 전체 기능 통합 테스트 (16번 테스트 항목 기준)

## 16. 테스트할 내용
- 영화 / 드라마 / 책 / 음악 검색이 각각 정상적으로 동작하는지
- 한글 검색이 정상적으로 동작하는지
- 검색 결과의 이미지와 정보가 올바르게 표시되는지
- 검색 결과를 선택해 Moa에 저장할 수 있는지
- 저장 시 필수 항목(콘텐츠 선택)만 있어도 등록되고, 별점 등 선택 항목 없이도 저장되는지
- 같은 콘텐츠를 중복 등록하려 할 때 안내 메시지가 나타나는지
- API 검색에 실패하거나 원하는 콘텐츠가 없을 때 직접 추가로 등록할 수 있는지
- 콘텐츠 이미지가 없거나 로딩에 실패했을 때 기본 이미지가 표시되는지
- 저장 · 수정 · 삭제 후 새로고침해도 데이터가 정확히 유지되는지 (삭제한 콘텐츠는 다시 나타나지 않는지 포함)
- 즐겨찾기 설정/해제, 감상 상태 변경이 카드와 상세 화면 모두에서 정상적으로 반영되는지
- 내 아카이브 검색이 제목/장르/제작자/개인 태그 기준으로 정상적으로 동작하는지
- 필터, 검색, 정렬을 동시에 적용해도 결과가 정상적으로 표시되는지
- 아카이브가 비어 있을 때와 검색 결과가 없을 때 안내 문구가 각각 올바르게 구분되어 표시되는지
- 등록 · 수정 · 삭제 시 아카이브 요약 개수가 정확하게 변경되는지
- API 요청 실패나 네트워크 오류가 발생해도 전체 페이지가 깨지지 않고 오류 안내가 표시되는지
- PC와 모바일 화면 모두에서 검색·필터·정렬 컨트롤과 카드 목록이 자연스럽게 보이는지

## 17. 향후 확장 계획
**현재 버전**: HTML + CSS + JavaScript + 콘텐츠 종류별 외부 검색 API + localStorage로 구현하는 개인용 콘텐츠 아카이브

**향후 확장 방향**: API 키 보호를 위한 서버/프록시 도입 → 로그인 → 서버/데이터베이스 → 여러 기기 간 데이터 동기화 및 사용자별 아카이브 순서로 점진적으로 확장할 수 있습니다. 이후 여유가 있다면 친구와 취향 공유, 콘텐츠 추천, 평점 통계, 데이터 백업/내보내기, 클라우드 저장 같은 기능도 고려할 수 있습니다.

로그인, 서버, 데이터베이스는 이번 프로젝트의 필수 구현 기능으로 지정하지 않으며, 어디까지나 향후 여유가 있을 때 고려하는 확장 옵션입니다.

## 18. 기대 결과
Moa는 단순히 콘텐츠 정보를 직접 입력하는 기록장이 아니라, 사용자가 실제 콘텐츠를 검색해 빠르게 자신의 아카이브에 추가하고 자신의 별점과 감상 기록을 남길 수 있는 실사용 가능한 개인 취향 아카이브로 완성하는 것을 목표로 합니다. 반복적인 정보 입력의 불편을 줄이고, 검색 → 선택 → 개인 기록 → 저장이라는 짧고 자연스러운 흐름을 제공합니다. 동시에 외부 API 연동, JavaScript, localStorage, 검색 · 필터 · 정렬, 사용자 인터랙션 등을 바이브 코딩을 통해 단계적으로 구현해보는 경험을 목표로 합니다.
