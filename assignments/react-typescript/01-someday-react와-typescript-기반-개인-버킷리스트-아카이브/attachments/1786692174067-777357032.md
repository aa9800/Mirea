# 프로젝트 계획서

## 1. 프로젝트명
Someday - 하고 싶은 경험을 모으고 이뤄가는 나만의 버킷리스트 아카이브

## 2. 프로젝트 개요
Someday는 "언젠가 해보고 싶은 일"들을 한곳에 모아 기록하고, 계획 중 → 진행 중 → 완료로 상태를 관리하며, 완료한 뒤에는 날짜와 후기를 남겨 지나온 경험을 다시 돌아볼 수 있는 개인 라이프 아카이브 웹페이지입니다. 단순한 할 일 목록(Todo)이 아니라, 하고 싶은 일을 모으고 이뤄내고 추억으로 쌓아가는 흐름 자체를 담는 것을 목표로 합니다.

## 3. 개발 배경 및 목적
- 해보고 싶은 일들이 메모, 머릿속, SNS 게시물 등 여기저기 흩어져 있어 한곳에 모아 관리하고, 이뤄낸 뒤에는 기록으로 남기고 싶은 필요에서 시작했습니다.
- 이 프로젝트의 데이터(하고 싶은 일, 목표일, 중요도, 후기 등)는 처음부터 끝까지 사용자가 직접 만들어내는 데이터이기 때문에, 별도의 백엔드나 외부 데이터 서비스 없이 프론트엔드 기술과 localStorage만으로도 실제 서비스에 가까운 완성도를 만들 수 있습니다. 이런 특성을 살려, React·TypeScript 같은 현대적인 프론트엔드 기술로 컴포넌트와 데이터 타입을 안정적으로 관리하면서 CRUD·검색·필터·정렬·통계 요약까지 구현해보는 바이브 코딩 학습을 목적으로 합니다.
- 로그인, 서버, 데이터베이스 없이도 실제로 계속 쓰고 싶어지는 결과물을 만드는 경험을 쌓는 데 목적을 둡니다.
- React, TypeScript, Tailwind CSS처럼 실무에서 널리 쓰이는 프론트엔드 기술 구성을 직접 다뤄보고, 기능이 늘어나도 컴포넌트와 코드를 안정적으로 관리하는 방법을 익히는 것도 목적으로 합니다.

## 4. 주요 사용자
- 하고 싶은 경험(여행, 취미, 도전, 배움 등)을 목록으로 관리하고, 이뤄낸 뒤에는 그 기록을 다시 들여다보고 싶은 개인 사용자 (개발자 본인)
- 여러 사람이 함께 쓰는 서비스가 아니라, 한 사람의 목표와 추억을 담는 개인용 아카이브입니다.

## 5. 프로젝트 범위 (필수 기능 / 추가 기능)

**필수 기능 (이번 프로젝트에서 구현)**
- 버킷 등록 (제목, 카테고리, 목표일, 중요도, 메모)
- 상태 관리 (계획 중 / 진행 중 / 완료)
- 완료 처리 및 완료 날짜 기록
- 완료 후 후기 작성
- 목표일 기반 D-Day 표시 및 "목표일 지남" 상태 표시
- 카드 형태로 표시, 수정, 삭제
- 즐겨찾기
- 검색 (제목 · 카테고리)
- 카테고리 필터 / 상태 필터 (동시 적용)
- 정렬 (목표일순 · 중요도순 · 등록순)
- "이룬 것들" 보기 (완료 상태 필터를 재사용하는 별도 탭/버튼)
- 전체 달성률 표시, 올해 목표 표시 (목표일이 올해인 버킷 기준)
- localStorage 저장
- 반응형 UI

**추가 기능 (기본 기능 완성 후, 여유가 있을 때 구현)**
- 사진 첨부 (1장, localStorage 용량 문제를 고려한 이미지 축소 처리 포함)
- 사진 여러 장 첨부
- 목표일 임박 알림/리마인더
- 카테고리별 달성 통계(그래프)
- 목록 공유하기
- 회원가입/로그인, 서버/데이터베이스를 통한 기기 간 동기화

## 7. 각 기능에 대한 상세 설명

### 7-1. 버킷 등록
제목, 카테고리(여행 · 취미 · 도전 · 학습 · 운동 · 음식 · 기타), 목표일, 중요도(상 · 중 · 하), 메모를 입력하는 폼입니다. 제목만 필수로 두고 카테고리 · 목표일 · 중요도 · 메모는 선택 입력으로 구성해, 일단 빠르게 등록하고 나중에 채워 넣을 수 있게 합니다. 등록 직후 상태는 자동으로 "계획 중"이 됩니다.

### 7-2. 상태 관리
각 버킷은 "계획 중 / 진행 중 / 완료" 세 가지 상태 중 하나를 가지며, 카드에서 버튼이나 드롭다운으로 바로 상태를 변경할 수 있습니다. 진행 중으로 바꾸면 실제로 시도하고 있음을, 완료로 바꾸면 다음 단계(완료 처리)로 이어집니다. 완료 상태에서 다시 계획 중이나 진행 중으로 되돌리는 경우, 완료 날짜(completedAt)는 초기화되지만 이미 작성한 후기(review)는 그대로 유지됩니다.

### 7-3. 완료 처리 및 완료 날짜 기록
상태를 "완료"로 바꾸는 순간 완료 날짜가 자동으로 기록됩니다. 완료된 버킷은 카드 디자인이 달라져(예: 체크 표시, 색상 변화) 계획 중 / 진행 중인 항목과 시각적으로 구분됩니다.

### 7-4. 완료 후 후기 작성
완료 처리와 함께, 또는 그 이후에 언제든 짧은 후기를 작성할 수 있습니다. "제주도에서 처음 해봤는데 생각보다 재밌었다" 같은 한두 줄의 소감을 남기는 용도로 안내 문구(placeholder)를 넣습니다.

### 7-5. 목표일 기반 D-Day 표시
목표일이 설정된 버킷에는 오늘 날짜를 기준으로 남은 기간을 D-30, D-7, D-Day 같은 형태로 계산해 카드에 표시합니다. 목표일이 지났는데도 상태가 완료가 아닌 경우에는 D-Day 대신 "목표일 지남" 상태를 표시해, 미뤄지고 있는 목표를 한눈에 확인할 수 있게 합니다. 목표일을 입력하지 않은 버킷에는 D-Day를 표시하지 않습니다. D-Day와 목표일 지남 여부는 별도로 저장하지 않고, 화면에 표시할 때마다 목표일과 오늘 날짜를 비교해 계산합니다.

### 7-6. 카드 형태로 표시
버킷은 제목, 카테고리 배지, 목표일과 D-Day(또는 "목표일 지남" 표시), 중요도, 상태, 즐겨찾기 여부가 담긴 카드로 표시됩니다. 완료된 카드에는 완료 날짜와 후기가 추가로 표시됩니다.

### 7-7. 수정
카드의 "수정" 버튼으로 제목, 카테고리, 목표일, 중요도, 메모, 후기 등 등록된 정보를 언제든 다시 고칠 수 있습니다.

### 7-8. 삭제
카드의 "삭제" 버튼으로 더 이상 필요 없는 버킷을 지울 수 있으며, 실수 방지를 위해 삭제 전 확인 절차(confirm)를 거칩니다.

### 7-9. 즐겨찾기
특히 애착이 가는 버킷은 하트 아이콘으로 즐겨찾기 설정/해제할 수 있고, 즐겨찾기한 항목만 모아보는 필터도 제공합니다.

### 7-10. 검색
검색창에 입력한 단어가 제목 또는 카테고리에 포함된 버킷만 화면에 표시합니다.

### 7-11. 카테고리 필터 / 상태 필터
카테고리(전체 · 여행 · 취미 · 도전 · 학습 · 운동 · 음식 · 기타)와 상태(전체 · 계획 중 · 진행 중 · 완료)를 각각 선택할 수 있으며, 두 필터와 검색어를 동시에 적용해 조건을 좁힐 수 있습니다.

### 7-12. 정렬
목표일순, 중요도순, 등록순(최근/오래된) 중 하나를 선택해 카드 순서를 바꿀 수 있습니다. 필터·검색 결과에도 동일하게 적용됩니다. 목표일순 정렬에서는 목표일이 없는 버킷을 목표일이 설정된 항목들 뒤에 배치합니다. 중요도순 정렬은 상 → 중 → 하 → 미설정 순서로 정렬합니다.

### 7-13. "이룬 것들" 보기
상단의 "이룬 것들" 탭(또는 버튼)을 누르면 지금까지 이뤄낸 경험만 따로 볼 수 있습니다. 이를 위한 별도의 조회 로직을 새로 만들지 않고, 내부적으로는 상태 필터의 "완료" 값을 그대로 적용하는 방식으로 구현해 코드 중복을 줄입니다.

### 7-14. 전체 달성률 / 올해 목표 표시
전체 등록 개수 대비 완료 개수를 백분율(달성률)로 계산해 보여줍니다. "올해 목표"는 목표일이 설정되어 있고 그 목표일의 연도가 올해(현재 연도)와 같은 버킷만 집계 대상으로 하며, 목표일이 없는 버킷은 올해 목표 통계에서 제외합니다. 올해 목표 개수와 그중 완료 개수를 함께 보여주고, 등록 · 수정 · 상태 변경 · 삭제 시 자동으로 다시 계산됩니다. 특히 목표일을 수정하면 해당 버킷이 올해 목표에 새로 포함되거나 제외될 수 있으므로, 수정 시에도 올해 목표 통계가 즉시 갱신되어야 합니다.

## 8. 화면 구성
- **헤더 영역**: 서비스 이름(Someday)과 짧은 소개 문구
- **아카이브 요약 영역**: 전체 달성률(progress bar 또는 퍼센트), 올해 목표 개수/완료 개수(목표일 연도가 올해인 버킷 기준), 카테고리별 개수(선택)
- **입력 영역**: 제목 · 카테고리 · 목표일 · 중요도 · 메모를 입력하는 등록 폼 (수정 시에도 동일 폼 재사용)
- **검색 · 필터 · 정렬 영역**: 검색창, 카테고리 필터, 상태 필터, 정렬 선택창, "이룬 것들" 탭/버튼(완료 상태 필터 재사용)
- **버킷 목록 영역**: 카드 그리드. 각 카드에 목표일 기반 D-Day 또는 "목표일 지남" 표시, 완료 카드는 완료 날짜 · 후기를 포함해 다른 스타일로 표시. 카드에는 상태 변경, 즐겨찾기, 수정, 삭제 버튼 포함
- **완료 처리 화면(모달 또는 카드 내부)**: 상태를 완료로 바꿀 때 완료 날짜 자동 입력 + 후기 작성을 함께 처리 (사진 첨부는 추가 기능 완성 후 이 화면에 반영)
- 등록된 버킷이 하나도 없거나 필터 결과가 없을 때는 안내 문구와 등록 버튼을 보여줍니다.
- PC에서는 여러 열 카드 그리드, 모바일에서는 한 열로 쌓이는 반응형 레이아웃으로 구성합니다.

## 9. UI/UX 디자인 방향
- 계획 중 / 진행 중 / 완료 상태를 색상과 배지로 뚜렷하게 구분합니다.
- 완료된 카드는 체크 표시나 톤이 다른 배경 등으로 "이뤄낸 경험"이라는 느낌을 시각적으로 살립니다.
- 중요도는 별 아이콘이나 색상 단계로 직관적으로 표시합니다.
- 목표일이 가까울수록(예: D-7 이내) 강조 색상으로 D-Day를 표시하고, 목표일이 지났는데 완료되지 않은 경우 경고 색상으로 "목표일 지남"을 표시합니다.
- 전체 달성률은 숫자보다 progress bar 같은 시각 요소로 보여줘 성취감을 느낄 수 있게 합니다.
- 카드에는 은은한 그림자와 둥근 모서리를 적용해 정돈된 느낌을 줍니다.
- 버튼과 입력창에 hover 효과를 넣어 완성도를 높이되, 과한 애니메이션은 사용하지 않습니다.
- 전체적으로 "해내고 싶은 일 → 이뤄낸 순간"이라는 감성적인 톤을 살리면서도 미니멀하고 깔끔하게 구성합니다.
- 검색 결과나 필터 결과가 없을 때, 등록된 버킷이 없을 때 각각 다른 안내 문구를 보여줍니다.
- 사진 첨부 기능은 추가 기능 완성 단계에서 카드와 상세 화면 디자인에 반영합니다.

## 10. 사용 기술
이번 프로젝트는 HTML/CSS/Vanilla JavaScript만 사용해야 한다는 제한을 두지 않고, Someday의 기능을 안정적이고 관리하기 쉽게 구현하는 데 도움이 되는 프론트엔드 기술을 적극적으로 사용합니다. 다만 별도의 백엔드나 외부 데이터 서비스 없이, 프론트엔드 기술과 localStorage만으로 구현하는 방향은 그대로 유지합니다.

- **React**: 버킷 카드, 등록/수정 폼, 요약 영역, 검색/필터/정렬 바, 완료 처리 모달 등을 컴포넌트 단위로 나누어 관리합니다. 기능이 많아질수록 화면을 독립된 컴포넌트로 쪼개 관리하기 쉽게 합니다.
- **Vite**: React 프로젝트의 개발 서버 및 빌드 환경으로 사용합니다. 빠른 개발 서버 실행과 간단한 빌드 설정이 학습 프로젝트에 적합합니다.
- **TypeScript**: 11번 데이터 구조에서 정의한 버킷 데이터의 형태(제목, 카테고리, 상태 등)와 함수의 입출력 타입을 명확히 관리해, 오타나 잘못된 값으로 인한 데이터 오류를 줄입니다.
- **Tailwind CSS**: 카드 UI, 상태별 배지, 반응형 레이아웃을 유틸리티 클래스로 빠르고 일관성 있게 구현합니다.
- **Lucide React**: 즐겨찾기(하트), 검색, 달력, 수정, 삭제, 완료 체크 등에 쓰이는 아이콘을 통일된 스타일로 사용합니다.
- **date-fns**: 목표일 기반 D-Day 계산, 완료 날짜 표시, 올해 목표 판별(목표일의 연도 비교) 등 날짜 관련 계산에 사용합니다. 실제로 계산이 복잡해지는 부분에만 사용하고, 단순 표시에는 굳이 사용하지 않습니다.
- **FileReader API**: 추가 기능 단계에서 사용자가 선택한 사진 파일을 읽어 미리보기 및 저장에 사용합니다. React 컴포넌트 안에서 파일 입력을 처리할 때 사용하며, 기본 기능 범위에는 포함하지 않습니다.
- **localStorage**: 서버와 데이터베이스 없이 사용자의 버킷 데이터를 브라우저에 저장하는 현재 방식을 그대로 유지합니다. 기본 기능 단계에서는 텍스트 위주 정보만 저장하고, 사진 데이터는 추가 기능 단계에서 함께 저장합니다.
- 외부 API, 로그인, 서버, 데이터베이스는 이번 프로젝트에서 사용하지 않으며, 필요성이 생기면 15번 향후 확장 계획에서 고려합니다.

## 11. 데이터 구조
각 버킷은 다음과 같은 정보를 가지도록 합니다. 제목처럼 항상 존재하는 값과, 카테고리·목표일·중요도·메모·완료 관련 정보처럼 선택 입력이거나 상황에 따라 없을 수 있는 값을 TypeScript 타입에서 `?`(optional)로 명확히 구분합니다.

```ts
type BucketCategory = "여행" | "취미" | "도전" | "학습" | "운동" | "음식" | "기타";
type BucketImportance = "상" | "중" | "하";
type BucketStatus = "계획 중" | "진행 중" | "완료";

interface Bucket {
  id: string;                    // 버킷을 구분하는 고유 식별자 (항상 존재, 등록 시 crypto.randomUUID()로 생성)
  title: string;                  // 하고 싶은 일 제목 (필수 입력, 항상 존재)
  category?: BucketCategory;       // 카테고리 (선택 입력)
  targetDate?: string;              // 목표일 (선택 입력) — 사용자가 date input에서 선택하는 값, YYYY-MM-DD 형식
  importance?: BucketImportance;     // 중요도 (선택 입력)
  memo?: string;                      // 메모 (선택 입력)
  status: BucketStatus;                // 상태 (등록 시 "계획 중"으로 자동 설정, 항상 존재)
  completedAt?: string;                 // 완료 처리 시 기록되는 날짜/시간 (완료 상태일 때만 값 존재), ISO 8601 형식
  review?: string;                       // 완료 후 후기 (선택 작성)
  photo?: string;                         // 사진 데이터 (base64 문자열) — 추가 기능에서만 사용하며, 기본 기능에서는 필수 필드로 취급하지 않음
  favorite: boolean;                       // 즐겨찾기 여부 (항상 존재, 기본값 false)
  createdAt: string;                        // 생성 시각 (항상 존재), ISO 8601 형식
  updatedAt: string;                         // 마지막 수정 시각 (항상 존재), ISO 8601 형식
}
```

새로운 버킷을 등록할 때 id는 별도의 ID 생성 라이브러리를 추가하지 않고, 브라우저 기본 API인 `crypto.randomUUID()`를 사용해 생성합니다.

D-Day와 "목표일 지남" 여부는 데이터에 저장하지 않고, targetDate와 오늘 날짜를 비교해 화면에 표시할 때마다 계산합니다. 이때 시각(시·분·초) 단위 차이가 아니라 사용자의 현재 로컬 날짜를 기준으로 한 달력 날짜 차이로 계산해, 자정 전후나 시각 차이 때문에 D-Day가 하루 어긋나게 표시되는 일이 없도록 합니다. date-fns로 계산하는 경우에도 이 기준(날짜 단위 비교)을 그대로 따릅니다.

## 12. 파일 구성
React + Vite + TypeScript 프로젝트 구조를 기본으로 하되, 처음부터 폴더와 파일을 지나치게 잘게 나누지 않고 역할이 명확하게 구분되는 경우에만 분리합니다.

```
Someday/
├── index.html               # Vite 진입 HTML
├── package.json
├── vite.config.ts
├── (Tailwind CSS 관련 설정 파일)  # 실제 설치 버전 및 Vite 연동 방식에 맞게 구성 (아래 설명 참고)
├── src/
│   ├── main.tsx              # 앱 진입점
│   ├── App.tsx                # 전체 화면 구성 및 상태 관리 시작점
│   ├── types/
│   │   └── bucket.ts           # 버킷 데이터 타입 정의 (11번 데이터 구조 기반)
│   ├── storage/
│   │   └── bucketStorage.ts    # localStorage 저장·조회·수정·삭제 함수
│   ├── utils/
│   │   ├── date.ts               # D-Day, 완료일, 올해 목표 계산 (date-fns 활용)
│   │   └── filterSort.ts         # 검색·필터·정렬 로직
│   └── components/
│       ├── BucketCard.tsx        # 버킷 카드
│       ├── BucketForm.tsx        # 등록/수정 폼
│       ├── SummaryBar.tsx        # 달성률·올해 목표 등 요약 영역
│       ├── FilterBar.tsx         # 검색·필터·정렬 컨트롤
│       └── CompleteModal.tsx     # 완료 처리(후기 작성 등) 모달
└── PROJECT_PLAN.md            # 프로젝트 계획서
```

개발 초기에는 App.tsx 안에서 상태 관리와 로직을 함께 시작하고, 코드의 역할이 뚜렷하게 나뉘는 시점부터 위 컴포넌트/유틸/스토리지 파일로 분리합니다. 한 파일이 지나치게 커지지 않도록 관리하는 것을 원칙으로 하며, 처음부터 폴더를 모두 채우지는 않습니다.

Tailwind CSS는 설정 파일의 이름과 형식(예: 설정 파일 존재 여부, 파일 확장자, PostCSS 연동 방식 등)이 설치하는 버전과 Vite 연동 방식에 따라 달라질 수 있으므로, 특정 파일 구조를 고정하지 않습니다. Tailwind 관련 설정은 실제 설치 버전과 그 시점의 권장 Vite 연동 방식에 맞게 구성합니다.

등록 · 수정 · 삭제 · 상태 변경 · 즐겨찾기 · localStorage 동기화 같은 로직이 많아져 App.tsx가 복잡해지는 경우, 아래처럼 상태 관리 로직을 담당하는 custom hook으로 분리할 수 있습니다. 처음부터 무리하게 만들지 않고, App.tsx가 실제로 복잡해질 때만 분리합니다.

```
src/
└── hooks/
    └── useBuckets.ts   # 버킷 등록·수정·삭제·상태 변경·즐겨찾기·localStorage 동기화 로직
```

## 13. 개발 단계 및 순서
1. **1단계 - 개발 환경 설정**: Vite + React + TypeScript 프로젝트 생성, Tailwind CSS 설정
2. **2단계 - 기본 구조**: 11번 데이터 구조를 바탕으로 버킷 타입(types) 정의, App.tsx 뼈대와 등록 폼(BucketForm), 카드 목록 영역의 기본 컴포넌트 구성
3. **3단계 - 등록 및 카드 표시**: 입력한 버킷 정보를 BucketCard 컴포넌트로 만들어 화면에 표시
4. **4단계 - 데이터 저장**: bucketStorage(localStorage)로 등록·조회 기능을 연결해 새로고침해도 데이터가 유지되도록 구현
5. **5단계 - 상태 관리**: 계획 중 / 진행 중 / 완료 전환 및 완료 날짜 자동 기록 구현
6. **6단계 - 완료 후기**: CompleteModal에서 완료 후 후기 작성 기능 구현
7. **7단계 - D-Day 표시**: date-fns를 활용해 목표일 기반 D-Day 계산 및 "목표일 지남" 상태 표시 구현
8. **8단계 - 수정 · 삭제**: 카드별 수정 · 삭제 기능 구현
9. **9단계 - 즐겨찾기**: Lucide 아이콘을 활용한 즐겨찾기 설정/해제 및 즐겨찾기 필터 구현
10. **10단계 - 검색 · 필터**: FilterBar 컴포넌트로 검색, 카테고리 필터, 상태 필터, "이룬 것들" 보기(완료 상태 필터 재사용) 구현 (동시 적용 포함)
11. **11단계 - 정렬**: 목표일순 · 중요도순 · 등록순 정렬 구현
12. **12단계 - 요약 영역**: SummaryBar에 전체 달성률, 올해 목표 개수, 올해 완료 개수(목표일 연도 기준) 표시 구현
13. **13단계 - 디자인 다듬기**: Tailwind 기반 상태별 카드 스타일, D-Day 강조 색상, 반응형 레이아웃 정리
14. **14단계 - 테스트 및 오류 수정**: 14번 테스트 항목을 기준으로 전체 기능 점검 및 수정
15. **15단계 - 추가 기능(사진 첨부)**: 기본 기능이 안정적으로 완성된 뒤, FileReader를 이용한 사진 1장 첨부와 이미지 축소 처리 구현

## 14. 테스트할 내용
- 제목 없이 등록을 시도했을 때 안내 메시지가 뜨고 등록이 막히는지
- 카테고리 · 목표일 · 중요도 · 메모를 비워두고 등록해도 정상적으로 저장되는지
- 상태를 계획 중 → 진행 중 → 완료로 바꿀 때마다 카드가 올바르게 갱신되는지
- 완료 처리 시 완료 날짜가 자동으로 기록되는지
- 완료 상태에서 계획 중 또는 진행 중으로 되돌렸을 때 완료 날짜(completedAt)가 초기화되고, 기존에 작성한 후기(review)는 그대로 유지되는지
- 후기 작성이 정상적으로 저장되고, 새로고침 후에도 유지되는지
- 목표일이 있는 버킷에 D-30, D-7, D-Day 등 남은 기간이 정확히 계산되어 표시되는지
- 목표일이 지났지만 완료되지 않은 버킷에 "목표일 지남"이 정확히 표시되는지
- 목표일을 입력하지 않은 버킷에는 D-Day가 표시되지 않는지
- 수정한 내용과 삭제한 항목이 새로고침 후에도 정확히 반영되는지
- 즐겨찾기 설정/해제가 정상적으로 동작하고, 즐겨찾기 필터가 정확한지
- 검색이 제목 · 카테고리 기준으로 정상적으로 동작하는지
- 카테고리 필터와 상태 필터를 동시에 적용해도 정상적으로 동작하는지
- 검색 · 필터 · 정렬을 함께 적용해도 결과가 정확한지
- 목표일순 정렬에서 목표일이 없는 버킷이 목표일이 설정된 항목들 뒤에 배치되는지
- 중요도순 정렬이 상 → 중 → 하 → 미설정 순서로 정확히 정렬되는지
- "이룬 것들" 탭이 상태 필터의 "완료" 결과와 동일하게 동작하는지 (별도 로직 없이 재사용되는지)
- 등록 · 수정 · 상태 변경 · 삭제 시 전체 달성률이 정확하게 갱신되는지
- 올해 목표 통계가 목표일 연도가 올해인 버킷만 포함하고, 목표일이 없는 버킷은 제외하는지
- 등록된 버킷이 하나도 없을 때와 필터/검색 결과가 없을 때 안내 문구가 각각 올바르게 구분되어 표시되는지
- PC와 모바일 화면 모두에서 카드 목록과 입력 폼이 자연스럽게 보이는지

**추가 기능(사진 첨부) 테스트 - 기본 기능 완성 후 진행**
- 사진을 첨부하면 정상적으로 미리보기 및 저장되는지
- 용량이 큰 사진을 첨부해도 축소 처리되어 오류 없이 저장되는지
- 사진이 없는 버킷에도 기존 기능이 정상적으로 동작하는지

## 15. 향후 확장 계획
**현재 버전**: React + TypeScript + Vite + Tailwind CSS + localStorage로 구현하는 개인용 버킷리스트 아카이브. 별도의 백엔드나 외부 데이터 서비스 없이 프론트엔드 기술만으로 구성합니다.

**향후 확장 방향**
- 사진 여러 장 첨부, 목표일이 다가오면 알림/리마인더를 보여주는 기능
- 카테고리별 달성 현황을 그래프 등으로 시각화하는 통계 기능
- 버킷리스트를 다른 사람과 공유하는 기능
- 로그인과 서버/데이터베이스를 도입해 여러 기기에서 같은 기록을 이어보는 구조로 확장

로그인, 서버, 데이터베이스, 외부 API 연동은 이번 프로젝트의 필수 구현 기능으로 지정하지 않으며, 어디까지나 향후 여유가 있을 때 고려하는 확장 옵션입니다.

## 16. 기대 결과
- 별도의 백엔드나 외부 데이터 서비스 없이, React·TypeScript·Tailwind CSS와 localStorage만으로 완성도 높은 개인 버킷리스트 아카이브 웹페이지가 완성됩니다.
- 하고 싶은 일을 등록하고, 계획 중 → 진행 중 → 완료로 이어지는 자연스러운 흐름 속에서 완료 후에는 날짜와 후기가 남아 하나의 경험 아카이브로 쌓이게 됩니다.
- 목표일 기반 D-Day 표시를 통해 다가오는 목표와 미뤄지고 있는 목표를 한눈에 파악할 수 있습니다.
- 전체 달성률과 올해 목표 현황을 통해 지금까지의 성취를 한눈에 파악하고 동기부여를 얻을 수 있습니다.
- 검색 · 필터 · 정렬 · 즐겨찾기를 통해 등록한 버킷이 많아져도 원하는 항목을 빠르게 찾을 수 있습니다.
- 컴포넌트 단위 설계와 TypeScript 타입 관리를 통해 CRUD, localStorage, 검색·필터·정렬 로직을 기본 기능에서 안정적으로 완성하고, 이후 사진 첨부 같은 추가 기능으로 자연스럽게 확장해보는 경험을 하게 됩니다.
- React, Vite, TypeScript, Tailwind CSS 같은 실무 프론트엔드 기술 구성을 처음부터 끝까지 다뤄보는 경험을 하게 됩니다.
